# IronNote

Дневник силовых тренировок для небольшой группы людей (семья, друзья).
Записывайте подходы, смотрите историю и прогресс. Приложение не составляет
программы, не даёт советов и не анализирует вас — оно хранит фактические данные и
считает по ним статистику.

Работает в браузере, mobile-first (от 320 px), тёмная тема.

**Многопользовательское, с ролями и защитой для публичного сервера.** Каждый
видит только свои тренировки; справочники ведёт администратор. Подробности модели
угроз — в [docs/security.md](docs/security.md).

## Что умеет

- **Пользователи и роли** — администратор создаёт учётные записи, задаёт
  временный пароль и роль; каждый участник видит только свои тренировки.
- **Справочники** — группы мышц (10 предзаполнены) и упражнения трёх типов:
  **с весом** (вес × повторения), **с собственным весом** (только повторения) и
  **на время** (бег, плавание, эллипсоид — минуты и, по желанию, дистанция).
  Изменять справочники может только администратор.
- **Шаблоны тренировок** — упорядоченный список упражнений с планируемыми
  подходами, повторениями и весом. Шаблон — заготовка, а не история.
- **Тренировка** — с нуля или по шаблону, подходы с весом и повторениями,
  тёплые подходы, заметки, копирование подхода в один тап, изменение порядка
  упражнений, завершение и последующее редактирование.
  Тренировка без единого выполненного подхода **не сохраняется** — приложение так и
  сообщает, чтобы в истории не появлялись пустые записи.
- **Правка и удаление истории** — можно исправить дату начала и продолжительность
  завершённой тренировки или удалить её целиком.
- **История** — завершённые тренировки в обратном порядке, фильтр по датам,
  длительность, число упражнений и подходов, тренировочный объём, а для кардио —
  время и дистанция.
- **Статистика** — тренировки и объём за период, разбивка по месяцам, рекорды по
  каждому упражнению, графики объёма и расчётного 1ПМ (формула Эпли). Для
  упражнений на время — суммарное время, дистанция и график времени; объём и 1ПМ
  к ним не применяются.

Незавершённая тренировка хранится в PostgreSQL: после перезагрузки страницы её
можно продолжить с того же места.

## Быстрый старт (Docker Compose)

Нужен только Docker с плагином Compose.

```bash
cp .env.example .env
```

Откройте `.env` и задайте **два** значения:

- `POSTGRES_PASSWORD` — пароль базы (`openssl rand -base64 24`);
- `IRONNOTE_ADMIN_PASSWORD` — пароль первого администратора. **Минимум 12
  символов**, буквы и цифры/символы. Сервер откажется стартовать с
  `change-me-please` или другим слабым значением.

```bash
docker compose up --build
```

Откройте <http://localhost:8080> и войдите как `admin` (или как указано в
`IRONNOTE_ADMIN_USERNAME`). Миграции применяются автоматически при старте backend.

Первый администратор создаётся из `.env` **только один раз** — когда таблица
пользователей пуста. Дальше значение из `.env` игнорируется, поэтому смена пароля
в приложении не «откатится» при перезапуске.

Остановить, сохранив данные: `docker compose down`.
Остановить и **удалить базу**: `docker compose down -v` (необратимо).

## Публикация в интернет

По умолчанию порт привязан к `127.0.0.1`, то есть приложение **недоступно
извне**, пока вы не настроите TLS. Это осознанно: cookie без TLS передаются
открытым текстом.

1. Получите сертификат (Certbot, Caddy, Traefik — на ваш выбор) и положите
   `fullchain.pem` и `privkey.pem` в `deploy/certs/`.
2. В `.env`:
   ```dotenv
   APP_BIND_ADDRESS=0.0.0.0
   IRONNOTE_COOKIE_SECURE=true
   IRONNOTE_PUBLIC_ORIGIN=https://gym.example.com
   ```
3. Запустите с TLS-оверлеем:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.tls.yml up -d --build
   ```

Что уже включено:

- Argon2id для паролей, сессии хранятся только в виде SHA-256;
- блокировка учётной записи после 5 неудачных попыток и лимит на IP;
- CSRF-токен на все изменяющие запросы, `SameSite=Lax`, `HttpOnly`, `Secure`;
- проверка владельца в SQL для каждой тренировки (нельзя открыть чужую по id);
- роли проверяются на маршруте и повторно в бизнес-логике;
- строгие заголовки безопасности и CSP без `unsafe-inline`;
- HSTS и редирект на https в TLS-конфигурации.

### Если сертификата пока нет, а проверить снаружи хочется

Можно временно поставить перед приложением любой TLS-прокси (Caddy в две строки)
и оставить `APP_BIND_ADDRESS=127.0.0.1`. Не открывайте порт без TLS.

## Первый сценарий работы

1. Войдите как администратор.
2. **Настройки → Пользователи → Добавить** — создайте учётные записи (например,
   `wife` и `brat`) с временным паролем; при первом входе они его сменят.
3. **Упражнения → Создать** — добавьте «Жим штанги лёжа» и выберите группы мышц.
4. **Тренировки → Начать → + Упражнение → + Подход** — введите вес и повторения,
   **Завершить**. Тренировка появится в «Истории» и в «Статистике» только у вас.

Пример кардио: создайте упражнение «Бег на дорожке» с типом «На время», добавьте
его в тренировку, введите 30 минут и дистанцию 5 км. Затем «Плавание» — 15 минут.
В истории появится время кардио 45 минут и дистанция, а объём останется отдельно
для силовых упражнений.

Проверка, что всё живо:

```bash
curl http://localhost:8080/healthz-api            # {"status":"ok"}
curl http://localhost:8080/api/muscle-groups      # 401 без входа — так и должно быть
```

## Запуск без Docker (разработка)

Нужны Go 1.23+, Node 20+ и PostgreSQL 14+.

```bash
# 1. База
createdb ironnote

# 2. Backend
cd backend
export DATABASE_URL="postgres://$(whoami)@localhost:5432/ironnote?sslmode=disable"
export APP_TIMEZONE=Europe/Moscow
go run ./cmd/api            # :8080, миграции применяются сами

# 3. Frontend (второй терминал)
cd frontend
npm ci
npm run dev                 # :5173, /api проксируется на :8080
```

Откройте <http://localhost:5173>.

## Тесты

```bash
make test                       # backend + frontend

cd backend && go test ./...     # юнит-тесты правил + интеграционные
cd frontend && npm run test     # компоненты и форматирование
```

Безопасность покрыта тестами (`backend/internal/api/security_test.go`):
анонимный доступ, изоляция тренировок между пользователями, запрет справочников
для обычного пользователя, обязательный CSRF, блокировка после неудачных попыток,
отзыв сессий при отключении пользователя, невозможность убрать последнего
администратора, отсутствие токена в открытом виде в базе.

Интеграционные тесты backend работают с настоящим PostgreSQL и создают для каждого
теста отдельную временную базу. Без `TEST_DATABASE_URL` они пропускаются, а не
падают:

```bash
cd backend
TEST_DATABASE_URL="postgres://user@localhost:5432/postgres?sslmode=disable" go test ./...
```

Юнит-тесты статистики (`internal/service/stats_test.go`) проверяют объём,
исключение разминочных подходов, формулу Эпли и то, что фактический 1ПМ не
смешивается с расчётным.

## Если при сохранении пишет «Запрос отклонён проверкой источника»

Это проверка CSRF: браузер присылает заголовок `Origin`, сервер сверяет его с
хостом, на который пришёл запрос. При обычной установке (UI и API на одном
адресе) ничего настраивать не нужно.

Сообщение появляется, если:

- вы открываете приложение по одному адресу, а запросы уходят на другой
  (например, `localhost` в браузере, но `IRONNOTE_PUBLIC_ORIGIN` указывает на
  домен) — приведите их к одному виду;
- перед приложением стоит прокси, подменяющий `Host` на внутреннее имя —
  укажите `IRONNOTE_PUBLIC_ORIGIN=https://ваш.домен`;
- запрос действительно пришёл с чужого сайта — тогда всё работает правильно.

## Если сборка падает на «failed to prepare extraction snapshot»

Это ошибка хранилища образов Docker, а не проекта: контейнер собирается, но Docker
не может разложить слой. Симптом в логе:

```
target backend: failed to solve: failed to prepare extraction snapshot
"extract-...": parent snapshot sha256:... does not exist: not found
```

Лечение по возрастанию радикальности (данные в томе `postgres-data` не
затрагиваются):

```bash
# 1. Почистить кэш сборки
docker builder prune -af

# 2. Пересобрать без кэша
docker compose build --no-cache

# 3. Перезапустить Docker Desktop (Windows/macOS) и повторить
docker compose up -d --build

# 4. Если не помогло — пересоздать хранилище образов
#    Docker Desktop → Settings → General → снять «Use containerd for pulling and storing images»
#    (или наоборот включить), затем Apply & Restart и снова:
docker compose up -d --build
```

Проверить, что дело не в коде: соберите стадии по отдельности.

```bash
docker build -t ironnote-backend ./backend
docker build -t ironnote-frontend ./frontend
```

Если падает только финальный экспорт, а `go build` и `npm run build` проходят —
это хранилище. Если ошибка в самих стадиях сборки — пришлите лог, разберём.

## Переменные окружения

Все переменные описаны в `.env.example`; значения в репозитории не хранятся.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `IRONNOTE_ADMIN_PASSWORD` | да | — | пароль первого администратора (мин. 12 символов) |
| `IRONNOTE_ADMIN_USERNAME` | нет | `admin` | логин первого администратора |
| `IRONNOTE_REQUIRE_STRONG_ADMIN_PASSWORD` | нет | `true` | отказываться стартовать со слабым паролем |
| `IRONNOTE_COOKIE_SECURE` | нет | `false` | `Secure`-cookie и HSTS; включать вместе с TLS |
| `IRONNOTE_PUBLIC_ORIGIN` | нет | — | внешний origin, напр. `https://gym.example.com` |
| `IRONNOTE_TRUSTED_PROXIES` | нет | `172.16.0.0/12` | кому верить в `X-Forwarded-For` |
| `APP_BIND_ADDRESS` | нет | `127.0.0.1` | адрес публикации порта |
| `POSTGRES_PASSWORD` | да | — | пароль роли PostgreSQL |
| `POSTGRES_USER` | нет | `ironnote` | пользователь БД |
| `POSTGRES_DB` | нет | `ironnote` | имя базы |
| `APP_PORT` | нет | `8080` | порт веб-интерфейса на хосте |
| `APP_TIMEZONE` | нет | `Europe/Moscow` | часовой пояс для разбивки по месяцам |
| `LOG_LEVEL` | нет | `info` | `debug` / `info` / `warn` / `error` |
| `DATABASE_URL` | да (backend) | — | строка подключения pgx |
| `TEST_DATABASE_URL` | нет | — | включает интеграционные тесты backend |
| `HTTP_ADDR` | нет | `:8080` | адрес прослушивания API |
| `CORS_ALLOWED_ORIGINS` | нет | пусто | нужно только при отдельном фронтенде |

## Решения, о которых стоит знать

- **Одна незавершённая тренировка.** Вторую начать нельзя (409): иначе «продолжить»
  становится двусмысленным, а данные теряются.
- **Удаление с защитой истории.** Упражнение, использованное в тренировке или
  шаблоне, удалить нельзя — предлагается архив. Удаление шаблона не меняет
  завершённые тренировки: при старте упражнения и подходы копируются в сессию.
- **Веса — `NUMERIC`, не `FLOAT`.** 1.25 кг остаётся 1.25 кг во всех суммах.
- **Один источник расчётов.** История и статистика считаются из одних и тех же
  строк одними и теми же функциями, поэтому не могут разойтись.
- **Безопасность прежде удобства.** Сессия в `HttpOnly`-cookie, CSRF-токен на
  изменения, блокировка после 5 неудачных попыток, изоляция данных в SQL, а не
  только в интерфейсе. Полная модель — [docs/security.md](docs/security.md).
- **Последнего администратора нельзя убрать.** Ни понижением роли, ни отключением,
  ни удалением: иначе приложение останется без управления справочниками.
- **Удаление пользователя удаляет его данные.** Поэтому в интерфейсе основное
  действие — «Отключить» (данные сохраняются, вход блокируется).

Подробнее — [docs/architecture.md](docs/architecture.md) и [docs/api.md](docs/api.md).
